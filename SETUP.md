# OYE THRIFT STORE - setup, deployment and operations

## What was wrong (findings from the code)

* **Everything ran on a managed Sitedrop backend** (`src/lib/db.ts`): accounts, products, images, carts. Its address and
  tenant id (`VITE_AUTH_BASE`, `VITE_TENANT_ID`) were blank in the exported `.env.example`. A site deployed without them
  cannot reach any product or image, and the data lives only inside that Sitedrop project - this is the most likely reason
  the catalogue "disappears" (project/preview lifetime, or a lapsed session). **I could not log into your Sitedrop project, so
  I cannot prove this; I can only say the code never stored blob URLs or expiring links in product records.**
* **Anyone could add products or upload files**: `addProduct` used an anonymous public write, and uploads went to an
  anonymous public bucket. Admin rights were only checked in the browser for pages.
* **No unique codes**, and no way to enforce them in a client-only store.
* **"ORDER VIA WHATSAPP" on the product page ignored sign-in and size/colour choices.** The message had no product code or
  category, and cart images from stored files rendered broken (an object was passed as `<img src>`).
* **Cart overwrite race**: a slow connection could save a guest/empty cart over a customer's saved cart.
* Admin owners had no "My Account" link, so no account-menu path to the dashboard.

## What it runs on now

Supabase (free tier is enough to start): Postgres for products and carts, Auth for accounts, Storage for images.
The design, pages and dashboard are unchanged. The Contact form and FAQ page still use the old Sitedrop services (see "Still open").

* **Admin rights** = a row in `admin_users`, readable only through `is_admin()`. The database (Row Level Security) refuses
  product writes and image uploads from anyone else, even if they call the API directly. The password is never in the code.
* **Product codes** (`OYE-TS-0001`...) are generated by a database trigger from a sequence that never moves backwards, are
  `UNIQUE`, cannot be changed by an update, and are never reused after a delete.
* **Images** go to the public `product-images` bucket; the product row stores the permanent path. If an upload fails the
  admin sees the error and nothing is saved. Removing an image from a product, or deleting a product, does not delete the file.

## Setup (about 20 minutes)

1. **Create a project** at supabase.com. Copy *Project URL* and the *anon public* key (Settings > API).
2. **Run the schema**: SQL Editor > paste `supabase/migrations/001_schema.sql` > Run. (Safe to re-run.)
3. **Auth settings** (Authentication):
   * Providers > Email: keep *Confirm email* **ON** (this is what stops anyone claiming the owner's address).
   * Email Templates > *Reset Password*: replace the link with the 6-digit code: `Your reset code is {{ .Token }}`
     (the existing Forgot-password page asks for a code).
   * URL Configuration: set *Site URL* to your deployed address.
4. **Configure the site**: copy `.env.example` to `.env`; fill `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`.
   Leave `VITE_WHATSAPP_NUMBER` (see the number note below).
5. `npm install`, then `npm run dev` to try it locally.
6. **Create the owner account** on the site (Sign Up with `yetqueen11@gmail.com`), click the confirmation email, then run
   `supabase/migrations/002_make_owner_admin.sql` in the SQL Editor. Sign out and in: **Admin Dashboard** now appears in the
   menu and on the My Account page. Do **not** reuse the password that was pasted in chat - choose a new strong one.
7. **Bring over existing products and images** (only if the old Sitedrop project still has them):
   ```
   export SUPABASE_URL=...  SUPABASE_SERVICE_ROLE_KEY=...  SITEDROP_API_BASE=https://sitedrop.ai  SITEDROP_TENANT_ID=...
   npm run import:legacy -- --dry-run     # look first
   npm run import:legacy                  # then import (re-runnable; skips what is already there)
   ```
   Existing products receive new codes in their original creation order. Get the tenant id from the Sitedrop project settings.
   Do this *before* the old project lapses.
8. **Deploy** `npm run build` -> upload `dist/` to Netlify, Vercel or Cloudflare Pages, adding the same `VITE_` variables in the
   host's settings. The site uses hash routing, so no redirect rules are needed. Redeploying never touches the data.

## Backups
* **Weekly, and before any bulk change:** `npm run backup` (needs the two secret values, run on your own computer). It saves
  `products.json` and every image into `backups/<date>/`. Copy that folder to Google Drive or an external disk.
* Turn on Supabase's own backups (Pro plan: daily) or run `pg_dump` from Settings > Database for the accounts/carts too.
* Restore: re-run `001_schema.sql`, upload the images back into `product-images/products/`, insert `products.json` rows
  (codes in the file are preserved if you insert with the trigger temporarily disabled; ask me for a restore script if needed).
